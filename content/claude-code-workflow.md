过去几个月，我一直在用 Claude Code 作为日常开发的主力工具。从最初的简单代码补全，到后来的完整项目搭建，这个工具彻底改变了我的工作方式。

这并不是一篇技术教程，而是我作为一个投行从业者，如何将 AI 编程工具融入到自己工作流中的真实记录。最让我意外的不是它能写代码，而是它能帮我 *思考*。

在这篇文章里，我会分享几个关键发现：

1. **终端优先**的工作模式比 IDE 插件更高效，因为它拥有完整的系统访问能力
2. Claude Code 最大的价值不在于生成代码，而在于**理解上下文**
3. 一个好的 prompt 等于一份清晰的需求文档
4. **自动化发布**流程让写作到上线只需要一个命令
5. 在投行场景下，它对文档处理和数据整理有独特的价值
6. 工具的边界在哪里——哪些事情它做不了

![Claude Code 的终端界面](https://images.unsplash.com/photo-1629654297299-c8506221ca97?w=1100&h=600&fit=crop)

在实际工作中，我发现一个有趣的模式：当你给 Claude Code 足够的上下文，它不只是执行指令，而是能提出更好的方案。

## 为什么选择终端而不是 IDE

很多人第一次接触 AI 编程助手，都是从 IDE 插件开始的。我也不例外。但当我尝试了 Claude Code 之后，就再也回不去了。

核心区别在于：IDE 插件只能看到你当前打开的文件，而 Claude Code 能看到整个项目。它可以直接读写文件、运行命令、搜索代码库、操作 Git。这不是一个「更聪明的自动补全」，而是一个真正的开发助手。

举几个具体的例子：

1. 我说「帮我找到所有调用了这个 API 的地方，然后统一改成新的参数格式」，它会用 `grep` 搜索、逐一修改、最后自动运行测试确认没有破坏任何东西
2. 我说「这个报错是什么意思」，它会读取相关源码、理解调用链、给出精确的修复方案——而不是丢一堆 Stack Overflow 链接

这种体验一旦习惯了，就很难再接受只能在编辑器里做补全的方式。

## 在投行工作中的应用

投行的工作节奏很快，同时处理多个项目是常态。我开始尝试用 Claude Code 来加速一些重复性的工作。

最典型的场景是文档处理。投行的日常充斥着各种格式的文件——Word、Excel、PDF。手动整理这些数据极其耗时。通过 Claude Code，我可以：

- 批量从 PDF 中提取关键数据，输出为结构化的表格
- 自动对比两个版本的合同文本，标注差异
- 根据模板快速生成标准化的报告初稿
- 从公开数据源抓取行业数据并生成分析图表
- 整理历史项目资料，建立可搜索的知识库

这些工作以前需要初级分析师花一整天来完成，现在很多可以在几分钟内搞定。当然，*最终的审核和判断依然需要人来做*，AI 只是加速了中间环节。

更深层的变化是思维方式。当你知道有一个工具可以快速执行你的想法时，你会更愿意去尝试。以前觉得「这个分析太复杂了，算了」的事情，现在会想「让我试试看」。

## 这个网站的搭建过程

这个网站本身就是一个很好的例子。整个搭建过程完全通过 Claude Code 完成：

1. **技术选型**：讨论了几种方案后选定 Quartz 4，因为它对 Obsidian 的原生支持最好
2. **初始化配置**：从 clone 仓库到配置字体、配色、布局，一气呵成
3. **自定义组件**：首页的标签分区导航是一个自定义 JSX 组件，Claude Code 根据我的需求直接生成

整个过程大概花了不到一个小时。如果我自己从零开始，阅读 Quartz 文档、理解其插件系统、写自定义组件，至少需要一整天。

> 最好的工具是你几乎感觉不到它存在的工具。

## 工具的边界

我不想把这篇文章写成一个无条件的安利。Claude Code 确实强大，但它有明确的边界：

- 它不理解你的业务逻辑。你需要清楚地告诉它你要什么
- 对于大型遗留代码库，它的理解能力会下降
- 它可能会「自信地」给出错误的方案，你需要有判断力
- 涉及敏感数据时需要谨慎——不要把客户信息喂给任何 AI 工具
- 自动生成的代码仍然需要 review，就像你 review 同事的代码一样

最后一点尤为重要。把 AI 当作一个能力很强但需要指导的初级同事，而不是一个万能的自动化机器，是目前最健康的心态。

## 我的建议

如果你也想尝试把 AI 工具融入工作流，这是我总结的几条经验：

1. **从小任务开始**。先用它做一些低风险的事情，比如写脚本、格式转换、数据整理
2. **学会写好 prompt**。你给的上下文越多，结果越好。不要说「帮我写一个网站」，而要说「帮我用 Quartz 4 搭建一个支持 Obsidian 标签的个人网站，参考 leerob.com 的排版」
3. **保持判断力**。AI 的输出不是终点，而是起点。你仍然需要 review、测试、调整
4. **建立自己的模式**。每个人的工作流不同，找到最适合你的使用方式
5. **记录你的经验**。写下来，就像我正在做的这样。写作是最好的学习方式
6. **持续关注新能力**。这个领域的进化速度很快，半年前不可能的事情现在可能已经很成熟了

这些建议不只适用于开发者。投行从业者、分析师、研究员——任何需要处理大量文本和数据的人，都可以从中受益。
